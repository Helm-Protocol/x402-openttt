TTTPS — Temporal Token for TLS Protocol IETF Draft · In Progress

TTTPS Documentation

TTTPS binds each payment attestation to a verifiable time anchor drawn from multiple independent sources — NIST, Roughtime, and a commitment chain resistant to replay, drift, and Byzantine manipulation. Any counterparty can verify the proof without trusting the issuer's clock.

Open-source reference implementation. IETF draft in active submission.

Quick Start

npm install openttt

Full source: github.com/helm-protocol/openttt
IETF draft: github.com/helm-protocol/openttt (submission in progress)

Public Demo API

No authentication required. Rate-limited.

POST
/api/demo/pot/generate
Generate a temporal attestation token. No API key required.
Request:
{
  "ctx_id": "your-context-id"
}

Response:
{
  "status":         "ok",
  "ctx_id":         "your-context-id",
  "timestamp_ms":   1747234567890,
  "grg_commitment": "a3f9...",
  "chain_digest":   "b7c2...",
  "signature":      "ed25519-base64...",
  "pubkey":         "ed25519-base64..."
}
POST
/api/demo/pot/verify
Verify a token generated by /generate. Paste the full response body.
Request:
(paste full response from /api/demo/pot/generate)

Response:
{
  "status":      "ok",
  "valid":       true,
  "attack_type": null
}

On attack detected:
{
  "status":      "ok",
  "valid":       false,
  "attack_type": "REPLAY"
}

Live endpoint: https://kenosian.com/api/demo/pot/generate

Attack Types Detected

REPLAY Timestamp reuse detected — token submitted more than once.
CLOCK_SKEW Timestamp drift exceeds acceptable threshold.
FLOOD Rate limit exceeded for this context ID.
TAMPER Ed25519 signature mismatch — payload modified after signing.
Request API Key For production access or IETF collaboration.
