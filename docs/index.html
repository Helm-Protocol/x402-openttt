x402 OpenTTT Documentation

OpenTTT (Open Temporal Trust Token) extends the x402 payment protocol with cryptographically verifiable time attestations. Every payment carries a tamper-evident timestamp binding that agents and smart contracts can verify independently — without trusting any single clock source.

Architecture

OpenTTT sits as a thin extension layer on top of the x402 payment standard. A paying agent constructs a temporal-attestation extension inside the standard x402 payload, then submits it through the normal x402 flow. The receiving service verifies the attestation before releasing the resource. 

┌─────────────────────────────────────────────────┐
│                  Paying Agent                   │
│  x402 PaymentPayload + temporal-attestation     │
└─────────────────────┬───────────────────────────┘
                      │  HTTP 402 → Payment
                      ▼
┌─────────────────────────────────────────────────┐
│              OpenTTT Verifier                   │
│  1. Decode temporal-attestation extension       │
│  2. Verify HMAC-SHA256 binding                  │
│  3. Check multi-source timestamp consensus      │
│  4. Enforce drift threshold (≤ 5000 ms)         │
│  5. Replay protection via nonce cache           │
└─────────────────────┬───────────────────────────┘
                      │  PASS → anchor on-chain
                      ▼
┌─────────────────────────────────────────────────┐
│           Base Sepolia Smart Contract           │
│  PoTAnchor event emitted per verified proof     │
│  Indexed by The Graph subgraph                  │
└─────────────────────────────────────────────────┘

Stratum Model

Each attestation carries a stratum field indicating the quality tier of the time source used. Higher strata indicate tighter synchronisation to authoritative time references.

StratumSource TypeTypical DriftUse Case
TURBO Institutional multi-source (NIST + Cloudflare) < 50 ms High-frequency arbitrage, settlement
FULL Single NTP source < 500 ms Standard cross-border payments
BASIC Device clock (best effort) < 5000 ms Low-stakes or offline-capable flows

The protocol rewards honest TURBO builders with faster settlement paths. Dishonest or degraded sources fall to FULL, creating a natural economic incentive toward precision without enforcement overhead.

API Reference — Verify

POST   /v1/verify

Verify a temporal-attestation extension and return a structured result.

Request Body

{
  "x402Version": 2,
  "extensions": {
    "temporal-attestation": {
      "timestampMs": 1747345200000,
      "nonce": "f4e5d6c7b8a9f4e5d6c7b8a9f4e5d6c7",
      "hmac": "a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4",
      "sources": ["NIST", "Cloudflare"]
    }
  }
}

Response — Pass

{
  "status": "PASS",
  "stratum": "TURBO",
  "mechanism": "Institutional Multi-source (NIST, Cloudflare)",
  "hmac_binding": "MATCHED",
  "drift_ms": 12,
  "drift_limit_ms": 5000,
  "nonce_seen": false,
  "verified_at": "2026-05-15T12:00:00.000Z"
}

Response — Fail

{
  "status": "FAIL",
  "reason": "HMAC_MISMATCH",
  "detail": "Computed HMAC does not match provided value.",
  "verified_at": "2026-05-15T12:00:01.123Z"
}

Failure Codes

CodeMeaning
HMAC_MISMATCHHMAC-SHA256 signature does not match payload
DRIFT_EXCEEDEDTimestamp drift exceeds configured threshold
NONCE_REPLAYNonce has already been seen in the cache window
INVALID_PAYLOADMalformed JSON or missing required fields
SOURCE_UNAVAILABLEInsufficient time sources responded

Integration — x402 Payload

OpenTTT is backwards-compatible with the x402 standard. Add the temporal-attestation key inside the extensions object of any existing x402 PaymentPayload.

Minimal Example

const payload = {
  x402Version: 2,
  scheme: "exact",
  network: "base-sepolia",
  payload: { /* standard x402 fields */ },
  extensions: {
    "temporal-attestation": {
      timestampMs: Date.now(),
      nonce: crypto.randomUUID().replace(/-/g, ""),
      hmac: await computeHMAC(secret, timestampMs, nonce),
      sources: ["NIST", "Cloudflare"]
    }
  }
};

Field Reference

FieldTypeRequiredDescription
timestampMsnumberyesUnix timestamp in milliseconds at time of payment construction
noncestringyes32-character hex nonce for replay protection
hmacstringyesHMAC-SHA256 of timestampMs + nonce under shared secret
sourcesstring[]noTime sources used — affects stratum classification

Integration — SDK Usage

Import the verifier directly in a Node.js or browser environment:

import { verifyTemporalAttestation } from '@helm-protocol/x402-openttt';

const result = await verifyTemporalAttestation(payload);

if (result.status === 'PASS') {
  // proceed with resource delivery
  console.log('Stratum:', result.stratum);
  console.log('Drift:', result.drift_ms, 'ms');
} else {
  // reject with 402
  return Response.json({ error: result.reason }, { status: 402 });
}

Integration — On-Chain Anchoring

Every verified proof can be anchored on Base Sepolia by emitting a PoTAnchor event from the OpenTTT smart contract. These events are indexed by The Graph and power the live dashboard. 

// Solidity event signature
event PoTAnchor(
    address indexed payer,
    uint256 indexed blockNumber,
    uint256 timestamp,
    bytes32 txHash,
    uint8   stratum
);

Query anchors directly from the subgraph: 

const query = `{
  poTAnchors(first: 100, orderBy: timestamp, orderDirection: desc) {
    id
    stratum
    timestamp
    txHash
    blockNumber
  }
}`;

const res = await fetch(
  "https://api.studio.thegraph.com/query/1744392/openttt-base-sepolia/v0.2.0",
  { method: "POST", body: JSON.stringify({ query }) }
);

Attack Matrix

The following known attack vectors are addressed by the protocol. All defenses operate at the cryptographic layer — no centralized authority is required to enforce them.

AttackVectorDefense Mechanism§ Ref
Replay Attack Resubmit valid attestation after expiry NONCE_REPLAY — nonce cache TTL § 12.1
Clock Skew Submit stale or future-dated timestamp DRIFT_EXCEEDED — ≤ 5000 ms threshold § 12.2
HMAC Tamper Modify payload fields after signing HMAC_MISMATCH — HMAC-SHA256 binding § 12.3
Flash Loan / Race Condition Exploit sub-block holding windows TURBO stratum requirement + block anchoring § 12.4
Source Spoofing Claim high-stratum sources without verification Multi-source consensus required for TURBO classification § 12.5

The live Defense Log on the dashboard shows real-time rejections with the triggering rule and reason.

GRG Pipeline

OpenTTT employs a three-stage error-correction pipeline for audit log integrity. This is the only blockchain implementation of this approach.

Stage 1 — Sequence Compression

Sequence compression for structured data streams. Removes redundancy in sparse event streams.

Stage 2 — Error Correction

Burst-error correction over encoded event blocks. Recovers from partial data loss without retransmission.

Stage 3 — Forward Error Correction

Perfect binary code for final integrity sealing. Provides a hard cryptographic bound on undetected errors.

Each audit log chunk passes through all three stages before being HMAC-bound and appended. This ensures verifiable tamper-evidence even if portions of the log are corrupted or withheld.
