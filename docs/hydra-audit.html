Hydra-Audit Documentation

Byzantine fault detection and timestamp integrity audit layer for distributed systems. Distributed clocks drift. Nodes lie. Audit logs get tampered. Hydra-Audit provides cryptographic proof of when events occurred — anchored to multiple independent time sources — and detects manipulation before it reaches your audit trail.

How it works

  • 01 Call /api/pot/generate with your context ID. A time anchor is collected from multiple independent sources and bound to the payload.
  • 02 Store the response as your audit token. Ed25519 signature seals the commitment. HMAC chain links events in sequence.
  • 03 Call /api/pot/verify at any later point. The engine detects drift, replay, or Byzantine manipulation against the original commitment.

Attack Types Detected

REPLAY Timestamp reuse — token submitted more than once.
CLOCK_SKEW Drift exceeds acceptable threshold from multi-source anchors.
FLOOD Rate limit exceeded for this context ID.
TAMPER Ed25519 signature mismatch — payload modified after signing.
