Hydra-KV Documentation

KV cache compression and smart routing for LLM inference clusters. In distributed LLM setups, prefill and decode nodes continuously transfer KV cache data over the network. At scale, 40–70% of that bandwidth is redundant. Hydra-KV intercepts and compresses that transfer, then routes it through the lowest-latency path across your cluster. No model changes. No infrastructure overhaul.

Architecture

  • 01 Prefill sidecar intercepts outbound KV cache transfers and compresses the payload. Identical blocks are deduplicated via CRDT.
  • 02 Router selects the lowest-latency decode node using real-time GapVec5 five-dimensional network signals.
  • 03 Decode sidecar receives, decompresses in-place, and serves the model. The model sees nothing different.

REST API — Port 8082

GET
/health
Liveness check. Returns "ok".
GET
/metrics
Prometheus text/plain metrics endpoint.
POST
/kv/route
Select optimal decode node for a KV cache transfer.
Request:
{
  "request_id":   1,
  "prefix_hash":  "abc123",
  "token_count":  512
}

Response:
{
  "decode_node":          "node-2",
  "estimated_ms":         18.4,
  "cache_hit":            true,
  "optimal_chunk_bytes":  65536,
  "rho":                  0.94
}
POST
/kv/signal
Push GapVec5 network metrics from sidecars.
POST
/kv/prefetch
Submit a prefetch hint ahead of an expected transfer.

Example

curl -X POST https://kenosian.com/api/kv/route \
  -H "Content-Type: application/json" \
  -d '{
    "request_id":  1,
    "prefix_hash": "abc123",
    "token_count": 512
  }'
